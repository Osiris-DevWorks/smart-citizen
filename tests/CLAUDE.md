## Pytest config

`pytest.ini` at the project root, not under `tests/` — placing it there makes rootdir resolve to `tests/` and breaks the `from src.X` imports CI uses. `pythonpath = . src` (project root for `from src.X`, `src/` for legacy `from utils.X`). Markers: `unit`, `integration`, `slow`, `critical`, `regression`.

## Test isolation

Tests should not depend on Registry state; mock `AppSettings` or use conftest fixtures.

The session-scoped autouse `no_real_install_detection_inputs` fixture in `tests/conftest.py` stubs two of the inputs first-run install detection reads: the RSI Launcher log under the real `%APPDATA%` and the listing of every fixed drive's top folders. Any test that resolves an install root with nothing saved (a channel switch does, and so does building a `MainWindow`) would otherwise reach the developer's real install. Session scope puts the stubs in place before module-scoped fixtures run, and the fixture patches both module copies tests import (`src.utils.settings` and `utils.settings`). `TestRealInstallDetectionInputsAreStubbed` in `test_sc_install_root.py` fails if either promise breaks. Tests of those inputs patch their own in, as `test_sc_install_root.py::TestScanUsesLauncherLog` does. Two things are not stubbed: the common-path walk (`iter_common_sc_install_locations`) still checks the real drive letters, because `TestScanCommonScInstallLocations` relies on it, and `_sc_scan_cache` keeps the first result per active channel for the rest of the run. The scan also reads the active channel, so tests that run it pin `AppSettings.get_active_channel` or use a temporary settings backend rather than reading the developer's registry. A test that needs a known detection result patches `_scan_common_sc_install_locations` itself, as `TestGetScInstallRootUsesDriveScan` does.
