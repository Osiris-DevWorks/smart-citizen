# tests/CLAUDE.md

Test suite layout. See the root `CLAUDE.md` for project context.

## Unit tests

Split by domain:

- `test_core.py` — INI parsing/merging/category extraction. `TestStringEntry` is `@pytest.mark.skip`: its constructor calls predate `category` and `status` becoming required positional args (cleanup pending). `parse_ini_file` skips a line with no `=` and keeps the lines after it, and parses a missing file to `{}` without logging a warning. `parse_ini_text` gives what `parse_ini_file` gives for the same text in a file (a BOM, CRLF, comments, a `,P` suffix, values with and without stripping).
- `test_missions.py` — mission rewards pipeline.
- `test_mission_engagement.py` — FPS / Ship / FPS&Ship engagement classifier from CIG loc-key naming.
- `test_mission_turrets.py` — turret detection from `SpawnDescription_ShipGroup Name="Turrets"` plus the `OverrideTurretHosility_BP` mission-variable signal. Fabricated XML, so no populated cache needed.
- `test_spawn_classifier.py` — 1.4.1 4-bucket spawn classifier (Crew / Boarders / Wave Hostiles / Wave Allies) that replaced the flat "Enemies" tally on mission descriptions.
- `test_mission_variant_tuple.py` — 1.4.1 regression: a variant adding an 11th tuple field threw `ValueError: too many values to unpack (expected 10)`. Locks the variant-tuple shape.
- `test_mission_desc_annotation_toggle.py` — 1.4.1 Tag-Builder toggle that suppresses `[CLASS-…]` component annotations (and since #492 armor weight tags, see `test_armor_blueprint_bullets.py`) inside mission descriptions while leaving the standalone component INIs annotated.
- `test_missile_name_tag.py` — 1.4.1: bomb name tags carry their ordinance letter, not size-only, so the variant column distinguishes `[BOMB-X-…]` from `[BOMB-Y-…]`.
- `test_commodity_journal.py` — 1.4.1 generator guard for the `commodity_journal` unpack crash when the crafting cache directory is missing. The SCO crafting index's material names follow the selected language (`ctx["loc"]`, not `tag_loc`), and its materials come in a fixed order, not the set order that changed with each run's string hashing (perf proposal review): the order they are first met, blueprint by blueprint, each blueprint's materials by name, so the index as a whole is not in name order. The test has eight materials in one blueprint, so a set order passes by chance about once in 40,000 runs.
- `test_blueprint_pools.py` — multi-source pool merge regression, component-style tag annotation, CIG-prefix strip, pool rank-tier label.
- `test_blueprint_filename_fallback.py` — #281 fuel-nozzle alias correction in `_name_from_blueprint_filename`, so all 8 variants resolve to their real names instead of garbled title-cased-slug fallback text in mission blueprint bullets.

## Pytest config

`pytest.ini` at the project root, not under `tests/` — placing it there makes rootdir resolve to `tests/` and breaks the `from src.X` imports CI uses. `pythonpath = .` (the project root, for `from src.X`). `src/` itself is deliberately not on the path: a test that imported a module by its short name (`from utils.X`) loaded a second copy of it, and a fake or patch set on one copy never reached code using the other, so now such an import fails at once (#510, see `test_import_paths.py`). Test files need no `sys.path` line of their own for `src`. Markers: `unit`, `integration`, `slow`, `critical`, `regression`.

## Test isolation

Tests should not depend on Registry state; mock `AppSettings` or use conftest fixtures.

The session-scoped autouse `no_real_install_detection_inputs` fixture in `tests/conftest.py` stubs two of the inputs first-run install detection reads: the RSI Launcher log under the real `%APPDATA%` and the listing of every fixed drive's top folders. Any test that resolves an install root with nothing saved (a channel switch does, and so does building a `MainWindow`) would otherwise reach the developer's real install. Session scope puts the stubs in place before module-scoped fixtures run, and the fixture patches `src.utils.settings`, the one copy every test imports (#510). `TestRealInstallDetectionInputsAreStubbed` in `test_sc_install_root.py` fails if either promise breaks. Tests of those inputs patch their own in, as `test_sc_install_root.py::TestScanUsesLauncherLog` does. Two things are not stubbed: the common-path walk (`iter_common_sc_install_locations`) still checks the real drive letters, because `TestScanCommonScInstallLocations` relies on it, and `_sc_scan_cache` keeps the first result per active channel for the rest of the run. The scan also reads the active channel, so tests that run it pin `AppSettings.get_active_channel` or use a temporary settings backend rather than reading the developer's registry. A test that needs a known detection result patches `_scan_common_sc_install_locations` itself, as `TestGetScInstallRootUsesDriveScan` does. `parse_launcher_log` checks each logged drive letter with `install_scanner._drive_exists`, which is not stubbed either, so a log test that names a drive outside `tmp_path` (a made-up `D:` or `Q:`) gives a different answer on a machine that has that drive. Patch `_drive_exists` in such a test, as `test_a_missing_drive_is_checked_once_and_nothing_on_it_is_probed` does. `tests/gui_window.py`'s `build_main_window` also saves an install root inside its temp folder, because a real `MainWindow` runs `ensure_user_cfg_language` on the active channel's `user.cfg`, and with nothing saved the old installer's registry key or the common-path walk can find the developer's real game.

Any test or fixture that builds a widget requests the session-scoped `qapp` fixture in `tests/conftest.py`, the run's only `QApplication`. Never create, destroy or replace a `QApplication` in a test, and don't define a module-level `qapp`. The app is made the first time something asks for it and kept until the session ends. In a run with GUI tests (Qt widgets already imported by the end of collection) the autouse `qapp_before_the_first_gui_test` fixture makes it before the first test, and a run without them (`pytest tests/test_core.py`) never builds one. `conftest.py` also sets `QT_QPA_PLATFORM=offscreen` (unless already set) when it is imported, before any test module, so no module needs its own copy. This used to be one module-scoped `qapp` per GUI module, each doing `QApplication.instance() or QApplication([])`: the module that made the app held its last reference, so the app was destroyed at the end of that module and the next GUI module made another (15 in one full run). Once the first app is gone, PyQt6 stops noticing when Qt deletes an object that Qt created itself (a view's scroll bars, menu actions, a status bar), so its wrapper keeps pointing at freed memory, and when Qt reuses that memory PyQt6 hands back the old wrapper for the new object. That crashed `test_tab_scrollbar_placement.py` with an access violation, roughly 1 full run in 5 on a Python 3.14 developer machine: `findChildren(QScrollBar)` returned a dead scroll bar's wrapper sitting on a live `QVBoxLayout`. The app's teardown also destroyed the windows `tests/gui_window.py` keeps alive. Because the app now stays alive, a test that fires a real `sys.excepthook` must stub `crash_logger.show_crash_dialog`, or the modal crash dialog blocks the run (`test_crash_handler.py`'s `fresh_crash_module` does). Two guards keep the churn from coming back: the module-scoped autouse `qapp_still_in_place` fixture checks the app when each module starts and again when it ends, so a module that destroys or replaces it, or makes its own, fails itself (the run's last module included), and `test_session_qapplication.py` checks that PyQt6 still marks the wrapper of a Qt-created scroll bar, menu action and status bar deleted when its parent dies, which fails if a second app appeared before it ran.

Every extraction checks free space before it writes (#482), so the session-scoped autouse `no_real_free_space` fixture in `tests/conftest.py` keeps the tests that run a real `extract_dataforge` or `extract_global_ini` on `tmp_path` (`test_extraction_working_folder.py`, `test_pak_extraction.py`, `test_extraction_stop.py`, `test_free_space_strings.py`, `test_folder_refused_strings.py`, `test_linked_cache_folder.py`, `test_base_ini_freshness.py`) off the free space of the drive they happen to run on: `shutil.disk_usage` reports 1 TiB free (the real call still runs first, so a missing folder still raises), and `pak_extractor._measure_volume` reports 4096-byte clusters and no quota figure. Like `no_real_install_detection_inputs`, it patches both module copies tests import (`src.utils.pak_extractor` and `utils.pak_extractor`); the wrapper keeps the real probe as `__wrapped__`. The check's own tests patch their figures in over it. `TestFreeSpaceCheck` in `test_extraction_working_folder.py` uses fake volumes and free figures per folder: every placement case, each refusal's exact intro and advice (`_intro_and_advice`: DataForge's intro, the cache advice beside the cache, the temp advice for work in `%TEMP%`), the stamp credit only with `raw/libs` beside the stamp and at least a cluster per file in both checks (at 4 KiB and 128 KiB clusters), a cache drive that is gone (`_cache_drive_gone`: each part skipped with a WARNING and the run failing as before, not refused), the real volume probe with both fallbacks made ones no drive has (a 1-byte cluster, and the label `?:` through `_drive_label`), the clean per-drive INFO line, and the check before the wipe (it still asks for a full copy of the kept files, to the byte, because a refused move falls back to one (#484), a stop during its walk of the old cache keeps that cache, its figures count the working folder on the cache's drive but not on another or an unmeasurable one, online-only files make no room, a cache with no folder left above it is skipped) and a full drive during a fallback copy, on a rename or on a stamp (both stamps are removed, and one that cannot be is logged both before the wipe and after the failure while the message stays the same). The online-only attributes are faked with a one-file `os.scandir` wrapper (`_listed_with`), because the cloud files driver sets them. The free-space tests at the end of `TestGlobalIniWorkingFolder` cover decision 1: a short cache drive moves the work to `%TEMP%` with nothing logged at WARNING, a short data drive alone does not move it and names only that drive, a data folder on `%TEMP%`'s drive is asked for base.ini only, the cache drive and `%TEMP%`'s both short give one WARNING, every refusal gives the global.ini intro and the plain advice (never the temp advice, which ends in the same sentence), and a cache drive that is gone moves the run to `%TEMP%` because its folder cannot be made. `test_free_space_strings.py` covers the rounding and every language's free-space keys and their placeholders, recorded from real refusals of `extract_dataforge` and `extract_global_ini` (each refused before any tool runs, so each picks its own intro), the figures in the cache folder tooltip, and `config.data_desc` in every language (french, portuguese_br and spanish keep their translator's `ht`, and while it still says 1,4 they must be on the key's *Needs human re-review* entry in `languages/TRANSLATIONS.md`). In `test_extraction_stop.py`: the workers' handling of an anticipated error (reported once with nothing at ERROR, or quietly as a stop after a Stop) and `_on_dataforge_extract_error` logging at WARNING. The function-scoped `english_ui` fixture (also in `conftest.py`) sets the real English `ui.json` for one test and restores the language another module left active; use it for any English text assert (`test_i18n_key_coverage.py` and `test_dataforge_timeout_message.py` do). The function-scoped `tmp_profile` fixture (also in `conftest.py`) puts a whole profile under `tmp_path` for a test that runs the real `AppSettings` paths: settings in a `JsonSettings` file, the registry build mode, and `%LOCALAPPDATA%`, the data folder and a Star Citizen install with LIVE and PTU folders, on LIVE with no cache folder override (the #494 tests use it). The function-scoped `slot_errors` fixture (also in `conftest.py`) records what reaches `sys.excepthook`, where Qt hands an exception raised in a slot, and returns the list: without a hook of its own, PyQt6 aborts the whole run on one. Use it for a test that clicks a button or emits a signal whose slot could raise (the #494 Enhancements tab, window path and Config tab tests do).
