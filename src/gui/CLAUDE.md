# src/gui/CLAUDE.md

GUI layer (PyQt6). See the root `CLAUDE.md` for project context and cross-cutting design decisions.

## Files

- `main_window.py` — main window with table, toolbar, filters, backup/restore, DataForge extraction trigger, worker orchestration. The largest file in the repo; runs the core workflow load→merge→edit→apply. Workers live in `workers.py`; pure-Python helpers (`validate_applied_file`, `filter_entry_indices`, `markdown_to_html`) live in their own modules and are wrapped by thin `MainWindow` methods. Owns `_stamp_frontend_version` — see *Frontend version stamp on apply* below. Less-frequent toolbar actions (restore backup, clear localization/cache, import/export INI, open loc dir) live under a **More** overflow `QMenu` (2.0). `_on_language_changed(language)` runs the language-switch pipeline (2.0, #30): cancel any in-flight loader, `i18n.set_language()` + `retranslate_ui()`, then `_apply_language_base_source()` repoints the `global` source at that language's base.ini (downloading it via `LanguageBaseDownloadWorker` when a URL is mapped; falling back to a cached copy, then to English), and `_reload_with_language_enhancements()` regenerates that language's enhancements first when the `.dataforge_stamp` is stale (skipped if no DataForge cache: prose loads without stat overlays). user.cfg's `g_language` is NOT set here; that happens at window init and apply-to-game time.
- `workers.py` — every `QThread` background worker plus the shared `AnimatedProgressDialog` and `SelectAllDelegate`. Workers: `FileLoaderWorker` (sources → `StringEntry` list + sort keys), `StartupSyncWorker` (refresh URL-backed sources at startup), `EnhancementsGeneratorWorker` (run `scripts/generate_enhancements_ini.py` in-process via `importlib.util`; takes a `language` param so output lands in that language's enhancements dir while annotation paths still parse the English base.ini), `P4kExtractWorker` (unp4k extract of `global.ini`), `DataForgeExtractWorker` (unp4k + unforge + post-extract patches), `LanguageBaseDownloadWorker` (2.0: fetch a non-English language's global.ini from its mapped URL into `cache\lang\{language}\base.ini`), `BlueprintLogScanWorker` (#222: scan a channel dir for "Received Blueprint" notifications via `blueprint_log_scanner.scan_channel`, watermark-aware — takes `(channel_dir, since)`, emits a `ScanResult`; stays read-only, all owned-set/watermark mutation happens on the main thread in `MainWindow._on_blueprint_log_scan_finished`). Each emits `progress` (str) and `progress_pct` (completed, total, message); `AnimatedProgressDialog.set_progress` consumes the latter. Exception: `AppUpdateCheckWorker` and `AppUpdateDownloadWorker` live in `src/utils/app_updater.py` because the workers, version comparison, and installer-asset picking belong together (#211).
- `markdown_renderer.py` — `markdown_to_html(text, text_color, base_color, link_color)` for About/Help. Pure-Python; the Qt caller passes palette colours so the converter has no Qt dep. Stash-and-restore code-span handling keeps `**` and `_` inside backticks literal (loc keys like `vehicle_Name*` shouldn't sprout `<em>` tags).
- `config_tab.py` — **Config Tab**: source management, drag-drop merge hierarchy, SC install path, DataForge extraction trigger. Also the language selector (2.0): emits `language_changed(str)` for `MainWindow._on_language_changed`, and hosts `LanguageSourceDialog` (the *Map Language File* button) for per-language base.ini URL overrides. Changing the data folder migrates existing data via `migrate_user_data_dir(move=True)`.
- `enhancements_tab.py` — **Enhancements Tab**: stats-overlay toggles, ship favorites prefix, DataForge extraction trigger, per-field mission-detail show/hide toggles (#121, persisted via `AppSettings._MISSION_FIELD_SETTING`). Emits `merge_requested` and `stats_pipeline_requested`. The whole tab sits in a `QScrollArea` so a small window squishes nothing (#145). Hosts `_NoScrollComboBox` (imported by `blueprint_tracker_tab.py` too — a `QComboBox` that lets the mouse wheel scroll the page instead of changing the selection when not focused).
- `blueprint_tracker_tab.py` — **Blueprint Tracker Tab** (#157; split out of the Enhancements tab into its own tab in 2.2.x, #222): the Available/Owned shuttle for blueprints that appear in missions' POTENTIAL BLUEPRINTS rewards, with search + Mission/Type/Class/Size/Grade filters. Owned items get an `[Owned]` tag woven into blueprint bullets wherever they appear (`src/utils/owned_items.py`). `set_blueprint_items(meta)` receives `{name: BlueprintItem}` from `MainWindow._recompute_owned` (computed by `src/utils/blueprint_meta.py::build_blueprint_metadata` from the loaded strings, which this tab can't see directly). Emits `owned_items_changed`, consumed by `MainWindow._recompute_owned`. The "Show tags on blueprint names" checkbox (#221, `AppSettings.get_/set_blueprint_show_tags`) toggles between `BlueprintItem.name` (bare, the stable matching identity) and `BlueprintItem.tagged_name` (the item's live item_Name value, tag and all) for display only — matching/filtering/Owned-tracking always use the bare name. Most of its i18n strings still live under the `enhancements.blueprints_*` namespace in `languages/*/ui.json` (unchanged on purpose — only the tab housing moved, not the strings' meaning); the tab's own title is `tabs.blueprint_tracker` / `blueprint_tracker.title`. The "Scan Logs for Owned Blueprints" button (#223 tab move; scanning itself is #222) emits `scan_logs_requested`; `MainWindow._run_blueprint_log_scan` resolves `AppSettings.get_channel_install_path()` and the last scan's watermark (`AppSettings.get_blueprint_log_watermark()`), runs `BlueprintLogScanWorker` (`workers.py`, wrapping `src/utils/blueprint_log_scanner.py`'s `scan_channel`) with a progress dialog, and `_on_blueprint_log_scan_finished` normalizes the returned raw names, merges new ones into `AppSettings.set_owned_items()`, and advances the watermark (monotonically, even when nothing new was found) so a re-scan only re-reads log growth since the last run.
- `log_tab.py` — **Log Tab**: in-app log viewer. Bridges Python `logging` to Qt via `_LogEmitter` (thread-safe). Level filtering, auto-scroll, export.
- `error_dialog.py` — `ErrorDialogHandler` + `_ErrorDialogEmitter` bridge `logger.error(...)` / `logger.critical(...)` to a Qt modal so users see failures without opening the Log tab. Same shape as `log_tab.py`: the handler is `setLevel(logging.ERROR)` so INFO/WARNING records skip it at the logger gate; the emitted record is marshalled to the main thread via `error_emitted = pyqtSignal(str, str)`. Cooldown + "N suppressed" coalescing live in `MainWindow._show_error_dialog` (not the handler), so the handler stays a stateless transport.
- `filter_header.py` — `FilterHeaderView`: `QHeaderView` subclass with a per-column `QLineEdit` filter row below header labels, debounced.
- `string_table_model.py` — `QAbstractTableModel` behind the strings `QTableView`. Replaces the old `QTableWidget.populate_table()`; renders visible rows on demand and sorts in Python (`sort()` override) rather than per-comparison `lessThan()`. Column constants live here: `COL_CATEGORY`, `COL_KEY`, `COL_DEFAULT`, `COL_CURRENT`, `COL_STAR`, `COL_ORDER`, `COL_CUSTOM`, `COL_STATUS`.
- `import_dialog.py` — `ImportConflictDialog` for resolving conflicts when importing INI files into user overrides. Per-key strategies: keep current, use imported, append, prepend, custom.
- `tag_mapping_dialog.py` — `TagMappingDialog`: modal editor for the Tag Builder's per-category variant mapping (Short / Medium / Long × class/ordinance/damage). Hides Medium for kinds with only Short/Long (missile ordinance) via `medium_column_visible`. Pure presentation; the underlying `TagConfig` lives in `src/utils/tag_builder.py`.
- `theme.py` — palette swap on `QApplication` plus branded font loading (`load_application_fonts()` registers the Hyperspace Race OTF from `assets/fonts/`). Theme-aware widgets rely on palette `WindowText`/`Text`; dim/secondary labels mark themselves with `setProperty("role", "secondary")` and the app-level QSS rule in `apply_theme()` recolors them on live theme swap. Progress-bar contrast uses the palette's `Highlight` role (Fusion's native chunk color) — do not add `QProgressBar::chunk` QSS, it switches Qt to a styled path that stops animating in indeterminate mode.
- `test_plan_panel.py` — **Test Plan dock** (#144): `TestPlanPanel`, the right-side `QDockWidget` checklist testers use to verify a release. Checkboxes grouped by section, a live progress bar, a persisted tester name, and Copy Report / Submit to Discord / Reset. Modelled on the Help dock (`_ensure_help_dock` → `_ensure_test_plan_dock` / `show_test_plan`, opened from the **More** menu). Check-state, tester name, and webhook URL persist via `AppSettings`; the plan content and report formatting are Qt-free in `src/utils/test_plan.py`; the Discord POST runs off-thread in `TestPlanSubmitWorker` (`workers.py`). Submit is disabled with no webhook configured (`AppSettings.get_test_webhook_url()` → stored override, then `SMART_CITIZEN_TEST_WEBHOOK_URL` env); Copy Report always works.
- `coach_mark.py` — `CoachMarkOverlay` plus `TutorialTour` for the in-app guided tour. Self-contained: the main window builds `CoachMarkStep` records (target widget, title, description, optional pre-action) and calls `tour.start()`. The overlay dims the window, spotlights the target, floats a callout with Back/Next/Skip; emits `finished(completed: bool)`.

## Design decisions

### Sortable columns require indirect row lookup
The table is a `QTableView` backed by `StringTableModel` (`string_table_model.py`), which holds a filtered/sorted list of indices into `self.entries`. Row index ≠ entry index when sorted or filtered. **All row→entry lookups go through `_entry_index_for_row(row)`** on `MainWindow` (which delegates to `self._model.entry_index_for_row(row)`). Direct indexing into `self.entries` by row number gives wrong results. Use the `COL_*` constants from `string_table_model.py`, not hard-coded column numbers.

### Frontend version stamp on apply
At apply-to-game time, `main_window._stamp_frontend_version(merged)` appends `\nLocalizations Enhanced with Smart Citizen v{VERSION}` (a literal `\n` — the loc-string line-break convention, same as the journal stamp) to the launcher's `Frontend_PU_Version` loc-key, putting the watermark on its own second line rather than crowding the build-info line. `_FRONTEND_VERSION_STAMP_RE` strips any prior stamp before re-applying — including the original " | "-separated form pre-2.3.0 installs have on disk — so the suffix doesn't pile up across applies or version upgrades. If the key is absent from the merge (older patches, custom configs), the stamp is skipped — never inserted. `tests/test_frontend_version_stamp.py` locks the no-double-stamp guarantee.

### Apply button starts green when nothing has changed (#387)
`MainWindow._build_apply_merged_dict(sources_dict, hierarchy)` factors the merge-and-stamp logic `apply_to_game` writes to disk into a shared, side-effect-free builder, so it can also drive `_entries_already_applied()` — called once, from `_on_loading_finished`, only on the very first load (gated on `_initial_load_done`, since every later reload already forces the button red via `_recompute_owned`'s `_mark_apply_dirty` call, correctly). That check parses the game's on-disk `global.ini` and compares it key-for-key against what a real apply would produce, walking the stock `base.ini` key set specifically — `merge_ini_files` only ever overwrites a key present in its structure-preservation source file, so a merged key `base.ini` lacks is never actually written and must be excluded from the comparison, or any profile with such a key would show a false "dirty" even right after a genuine apply. Falls back to the pre-existing conservative `True` (red) default on any doubt: no applied file yet, no stock `base.ini` loaded, or any error along the way.
